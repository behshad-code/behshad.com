# Repository instructions

Applies to this repository and all website development tasks.

1. Read `README.md` before editing. Follow its approved preview hosting and security rules. The approved review method is a complete, navigable GitHub Pages sandbox in this repository at one stable `https://behshad.com/sandbox/<feature>-review/` entry URL. Keep an existing approved review URL unless the user requests a change.
2. Never create or share raw.githack.com, rawcdn.githack.com, RawGit, or equivalent third-party rendering/caching previews. Never introduce an alternative preview provider without the user's explicit instruction.
3. Public repositories and GitHub Pages sandboxes are public, even with `noindex`. Never commit credentials, confidential source documents, or private working material to any public branch.
4. Record current `main` before starting; inspect open work and preserve concurrent changes. Use a scoped branch and pull request. Do not force-push, bypass protections, merge unrelated feature drafts, or change DNS/CNAME as a workaround.
5. Preserve approved layouts, content, artwork, Ballot Compass, and analytics. Make surgical changes. Do not publish feature changes to the live site without explicit user approval. Do not delete active development branches or sandboxes as unrelated cleanup.
6. Verify source boundaries and links, then actually test the hosted sandbox on desktop and mobile. State unavailable checks honestly; a successful commit or build alone does not prove browser behavior.
7. Promote the exact approved content through a scoped PR. Verify the production deployment before separately removing obsolete sandbox files. Never claim that removing a branch or purging a cache erases public history or all existing copies.
